## Sprint 划分

### Sprint 0 —— 技术债清理与仓库工程化 ✅ 已完成

**目标**：把「能跑但会泄露」的仓库，变成可以安全 push 到 GitHub 的工程化仓库。

**范围**：
- 审计 30 项技术债，P0 全 12 项关闭
- 6 个死代码云函数 + npm 缓存清理
- 真实用户数据与业务数据脱敏替换
- 7 组密钥外移到统一配置层
- 作者署名统一、`ai-chat-mask` 语法修复、`.gitignore` / `LICENSE` / `README` / `docs/` 落地

**增量**：仓库可干净 clone，不含凭据与真实数据；`npm test` 可校验 91 个 JSON。

**详细报告**：[`技术债清理报告.md`](./技术债清理报告.md)

---

### Sprint 1 —— 登录与账户持久化 ⏳ Planned

**目标**：在既有 uni-id 链路上补齐安全加固与会话健康检查。

**范围**：
- `auth-gateway` 中间层（不改 uni-id-co 源码，避免升级冲突）
- 四项安全修复：CSPRNG 验证码 / 错误次数锁定 / 发送频控 / 手机号类型严格校验
- `session-audit` 云函数 + `utils/session.js`（会话健康检查层）
- `uni-id-users` 扩展字段：`login_count` / `last_login_at` / `source`

**完成标准**：手机号验证码登录链路可走通；新用户入库且 `login_count` 可验证；路由守卫生效；会话过期能被前端感知并自动处理。

---

### Sprint 2 —— Agent 编排层 ⏳ Planned

**目标**：把「问答壳」升级为真正可编排、可降级、可观测的 Agent。

**范围**：
- `agent/core/`：planner / executor / memory / fallback
- `agent/tools/`：注册表 + `user-stats` / `server-time` / `echo`
- `agent/adapters/`：`rule-adapter`（默认，零依赖）/ `llm-adapter`（可选）
- `agent/tests/`：4 类场景单测（正常意图 / 多工具串行 / 未知意图降级 / 参数校验失败）
- 前端「Agent 演示」页面：输入 → 规划 → 执行 → 查看 trace

**完成标准**：单测全绿；规则适配器零外部依赖可运行；trace 环形缓冲区保留最近 20 条。

---

### Sprint 3 —— 数字人交互层 ⏳ Planned

**目标**：自研 Canvas 2D 形象 + 口型同步，并与 Agent 联动。

**范围**：
- `digital-avatar/renderer/canvas-avatar.js`：Canvas 2D 绘制头部/眼睛/嘴巴
- `digital-avatar/bridge/lipsync.js`：文本 → 口型参数序列（纯规则映射）
- `digital-avatar/controller/avatar-controller.js`：`speak` / `stop` / `setExpression`，含队列与打断
- `digital-avatar/adapters/tts-adapter.js`：默认 noop
- `agent/tools/avatar-speak.js`：Agent → 数字人联动
- 前端「数字人演示」页面

**完成标准**：口型序列连续变化可观察；`stop()` 立即打断并复位；Agent 能触发口播；`lipsync` 纯函数单测通过。

### Sprint 4 —— 打包配置与上线文档 ✅ 已完成

**目标**：可交付的打包与上线文档，不声称已产出 APK。

**范围**：

  步骤含 checkout / setup-node / 装依赖 / 跑全部测试 / 密钥扫描 / 构建 / 上传 artifact

  APK 签名打包 → 冒烟测试清单 → GitHub Releases 分发）

- Known Issues 如实列出：APK 未实际打包、短信为模拟模式、

## 迭代节奏

每个 Sprint 采用同一节奏：

| 阶段 | 产出 |
|---|---|
| **Plan** | Sprint 开始时给出要改 / 新增的文件清单 |
| **Build** | 按清单实施，每批次执行后立即校验，失败即停并报告 |
| **Review** | Sprint 结束时给出摘要：完成了什么 / 如何验证 / 遗留什么 |
| **Commit** | 提交信息体现 Sprint 编号与变更范围，README 对应章节同步更新 |

README 的 git 历史完整反映这一迭代过程 —— 每个 Sprint 的 Review 摘要都写入对应章节，
而非一次性补齐。
